## 一、性能优化

### 1.1 LLM 推理：CPU → CUDA GPU（5.9 → 46 tok/s）

- 下载 llama.cpp CUDA 12.4 预编译二进制（b8864）+ `cudart` DLL 补充包
- 无需安装 CUDA Toolkit，自带 `cudart64_12.dll`
- 调优参数：`-ngl 36 -c 2048`（36 层全上 GPU，显存占用 ~2.2GB/4GB）
- 纯生成速度从 5.9 tok/s 提升到 **46.66 tok/s**，提升 **8 倍**

### 1.2 模型懒加载（启动 30s → 2-3s）

- `OllamaEmbedder`：`BGEM3FlagModel()` 初始化推迟到首次 `embed()` 调用
- `CrossEncoder`：已是类级别懒加载（`_get_reranker()` 首次调用才初始化）
- `backend/main.py` lifespan 精简为配置校验 + 启动后台队列处理器
- FastAPI 启动从 ~30s 降到 **2-3 秒**

### 1.3 流式输出（SSE）

- `generator.py`：新增 `generate_stream()`，逐 token 流式返回
- `api/query.py`：新增 `/api/query/stream` 端点，`text/event-stream`
- `_clean_response()`：提取公共幻觉截断函数，`generate()` 和流式端点复用

### 1.4 请求队列（并发安全）

- `asyncio.Queue` + 最大并发 1（单模型串行推理）
- 队列满返回 HTTP 503，防止并发 OOM
- 后台协程 `_process_queue()` 在 lifespan 中启动

## 五、踩坑记录

### 5.1 Vulkan 在 GTX 1650 Ti 上不工作

**现象**：llama.cpp Vulkan 版推理速度只有 3.4 tok/s，比旧 CPU 版（5.9 tok/s）还慢。

**原因**：GTX 1650 Ti 没有 Tensor Core，Vulkan 编译版未针对此卡优化。

**解决**：换用 CUDA 12.4 预编译二进制（b8864），配合 `cudart-llama-bin` DLL 补充包。纯生成速度达到 **46.66 tok/s**。

**教训**：低端 NVIDIA 卡优先选 CUDA 后端，Vulkan 更适合 AMD/Intel 显卡。

---

### 5.2 CUDA 全层加载导致显存溢出

**现象**：`-ngl 99` 后推理速度只有 0.6 tok/s，比 CPU 还慢 10 倍。

**原因**：模型 1.96GB + KV Cache + Compute Buffer 超过 4GB 显存，触发内存交换。

**解决**：逐步测试最优值，最终 `-ngl 36 -c 2048`，显存占用 ~2.2GB/4GB，留足余量。

---

### 5.3 Reranker 与 llama-server 抢 GPU 显存

**现象**：首次查询报 `torch.OutOfMemoryError: CUDA out of memory`。

**原因**：llama-server 占用 ~2.2GB/4GB 显存，PyTorch CrossEncoder 默认也加载到 GPU，剩余 0 字节。

**解决**：`DEVICE` 默认改为 `"cpu"`，`CrossEncoder(device="cpu")` 显式指定 CPU。

---

### 5.4 Reranker CPU 推理是最大瓶颈

**现象**：预热后每次查询 12-16 秒，首 token 延迟 10 秒+。

**时间分布**：

| 阶段 | 耗时 | 占比 |
|------|------|------|
| Embedding | 1-2s | 10% |
| 检索 | <1s | 5% |
| **Rerank** | **8-12s** | **65%** |
| 生成 | 2-4s | 20% |

**后续优化方向**：减少候选数（8→4）、换轻量 Reranker、或升级 GPU 后将 Reranker 上 GPU。

---

### 5.5 Gradio 6.0 流式生成器性能问题

**现象**：Gradio Web UI 显示 36-50 秒，直接调 API 只要 12-16 秒，差距 3 倍。

**原因**：Gradio 6.0 对生成器（generator）事件处理器有性能问题。逐 token yield 触发 UI 重渲染累积大量开销。

**解决**：前端改用非流式 `/api/query` 端点，一次性返回。耗时从 36-50s 降到 **16-20s**。

```python
# ❌ 流式（Gradio 6.0 性能差）
def respond(msg, history, mode, top_k):
    yield ...
    for partial in query_api_stream(...):  # 逐 token yield，卡 3 倍

# ✅ 非流式（正常速度）
def respond(msg, history, mode, top_k):
    answer = query_api(...)  # 一次性返回
    return "", history
```

### 5.6 批处理文件编码 + 路径引号问题

**解决**：用 Python `start.py` 替代，`subprocess.Popen` 天然避免编码和引号问题。
